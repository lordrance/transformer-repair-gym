# LICENSE_AUDIT

Audited 2026-08-10 via the GitHub REST API (`/repos/{owner}/{repo}` and
`/repos/{owner}/{repo}/license`), not from memory or from README badges.

## Headline result

**Phase 0 ships zero third-party code.** `trgym/reference/tiny_gpt.py` and
`trgym/reference/train_loop.py` were written from scratch for this project, and
every task is generated by mutating *those* files. The repositories below were
used as **evidence for what bugs are real** (see `REAL_BUG_EVIDENCE.md`), which
is a use of published facts, not of copyrightable expression.

That was a deliberate design choice, not luck: deriving tasks from a
first-party reference removes the licensing question from the critical path and
keeps the gold patch trivially equal to the reference file.

## Decisions taken

1. **`llm-speedrunner` is excluded.** A non-commercial restriction is
   incompatible with a portfolio repository intended to be publicly usable, and
   with publishing to a hub where labs may train on the content. It remains
   useful as *reading* for task design. This confirms the reviewer's flag.
2. **RE-Bench is excluded from Phase 0.** Not because it is bad — it is a good
   held-out candidate — but "no license file" is a blocking answer, not an
   ambiguous one. Revisit only with an explicit grant.
3. **`transformers` PR-mirroring is deferred, not rejected.** Apache-2.0 permits
   it. It is deferred because attribution bookkeeping for hundreds of derived
   instances is real work that belongs in the flagship phase, and because
   Phase 0 needed to answer a feasibility question, not a scale question.
4. **SWE-smith is a method, not a dependency.** Its contribution here is the
   demonstration that procedural bug injection scales. We copied the idea and
   wrote our own mutation layer (`trgym/tasks/spec.py`), which is ~40 lines
   because our mutations are declared literal edits rather than AST rewrites.

## Portability finding (not a licensing issue, but discovered during this audit)

`verifiers==0.3.0`'s **`verifiers.v1` subpackage does not import on Windows**:

```
verifiers/v1/runtimes/limiters.py:12: import fcntl
ModuleNotFoundError: No module named 'fcntl'
```

`fcntl` is POSIX-only. The top-level `verifiers` package — `Environment`,
`SingleTurnEnv`, `Rubric`, `load_environment`, the CLI — imports and runs fine,
which is why this project works. But the v1 harness/runtime layer, including
`ModalRuntime`, is unreachable on this machine.

Consequences:
- Phase 0 is unaffected: it uses `vf.SingleTurnEnv` + `vf.Rubric` and its own
  subprocess sandbox.
- The flagship's multi-turn harness and any Modal-backed runtime will need WSL2,
  a Linux container, or a Linux host. **Budget for that; do not discover it
  the week of a paid training run.**

## Attribution to carry into any public release

If the flagship later vendors code from the MIT/Apache/BSD sources above, ship
a `THIRD_PARTY_NOTICES.md` containing each project's license text and a
statement of modifications. Nothing is required for Phase 0 as shipped.
