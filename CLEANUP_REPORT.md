# CLEANUP_REPORT

Release cleanup for the public repository. Every deletion below was either regenerable
output or local execution debris; no unique evidence was removed.

---

## Rule applied

A file was kept if it serves at least one of: source, tests, task definitions, canonical
reproducibility evidence, final reports, documentation, CI, or dependency reproduction.
Everything else is local execution debris.

The one judgement call worth stating: **messy-looking artifacts were kept when a reported
number depends on them.** `artifacts/` is 6.3 MB of trajectory `.jsonl` and gate JSON, and
it stays, because `scripts/build_final_metrics_summary.py` regenerates every headline figure
from exactly those files. Deleting them to tidy the tree would leave the README quoting
numbers nothing in the repository can reproduce.

**Scripts were examined and kept.** Many are one-off audit tools that nothing imports, which

below they are reproducibility tooling: deleting `fuzz_verifier.py` would leave
`VERIFIER_FUZZ_AUDIT.md` unreproducible. Unused ≠ redundant.

Of the 398 MB remaining, **376 MB is `.venv`** and 11 MB is `.git`. The actual source,
tests, docs and evidence total ≈11 MB, which is what a clone transfers — `.venv` is ignored
and never uploaded.

### `.venv` was deliberately not deleted

It is 376 MB and regenerable from `uv.lock`, so it is the obvious reclamation target. It was
kept because the release sequence still needs a working interpreter for the clean-checkout
validation, and deleting it mid-release would trade 376 MB for the ability to verify what is
being published. It is safe to remove afterwards with `rm -rf .venv` and rebuild via
`uv sync --extra dev --extra inspect`; the fresh-clone reproduction already proves that path
works from the lockfile alone.

### Python caches

172 `__pycache__` / `.pytest_cache` / `.ruff_cache` directories exist outside `.venv`. The
recursive delete could not be executed in this session (the harness safety classifier
refused the `find -exec rm` form). They are ignored by `.gitignore`, so **none of them reach
the repository**; they cost local disk only, and `find . -name __pycache__ -type d -prune
-exec rm -rf {} +` clears them at any time.

## Docker

No Docker objects were pruned. The images this project uses — `trgym-sandbox:latest` and
`trgym-v1:latest` — are required to reproduce the isolation canaries, `tests_v1`, and the
Tier S freeze, and the machine hosts unrelated containers from other work. An
indiscriminate `docker system prune` would have destroyed those, so nothing was removed.
